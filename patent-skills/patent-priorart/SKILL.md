# Prior-art search workflow

Build a verifiable novelty/inventiveness assessment for a technical solution. Track progress with TodoWrite.

## Dispatch rules

- Sub-agents start fresh: every dispatch must be self-contained — the technical solution (or disclosure path), search scope, file paths, constraints. Never say "as discussed".
- One case, one folder: reuse the case's existing folder if there is one; otherwise default to `patent<NNN>/` — NNN is a 3-digit zero-padded sequence: scan the workspace for existing `patent*` folders and use max+1 (first case = `patent001`); the user naming another location wins. Pipeline paths below are relative to the case folder.
- Citation integrity is the core risk of LLM-assisted searching: every reference must carry a resolvable URL (checked, with access date) — a patent number via Google Patents or Espacenet, a paper via DOI. References with no resolvable URL are treated as unverified. No plausible-looking phantom references, ever.
- The assessment reports what the found references actually disclose — overstating the prior art kills the case as surely as missing it.
- Independent steps run in parallel (dispatch in the same message) — but parallel writers never share one output file.
- Every agent must persist its findings to its own file (`review-findings.md`, `candidates-*.md`, …), not just return them in its final message — a finding that exists only in a subagent message is lost to the pipeline and forces re-transcription.
- Communicate with the user in the user's language; the report's language follows the user's.

## Pipeline

1. **Setup — confirm scope with the user**: the technical solution (from `disclosure.md` if it exists, else the user's description), target jurisdiction, and the expected filing/priority date (the cutoff — only publications predating it count as prior art). Decompose the solution into technical features and save the confirmed decomposition → `prior-art/features.md` (the row axis of everything downstream).
   **Inventory prior search work first.** Cases often carry earlier scout/check documents (patent scouts, claims-checks, direction surveys). List them in `features.md` as a "verified pool" (with each item's verification level: full-text / claims-level / abstract-only), define this round's increment (start = the previous snapshot date), and have researchers target the increment plus legal-status updates — re-verifying what prior rounds already verified wastes the budget and rewrites conclusions for no reason. Gaps the prior work flagged become this round's explicit tasks.
2. **Search — dispatch `researcher`** (parallel dispatches per feature cluster, one output file each)
   Queries in Chinese and English with IPC/CPC classification codes + keywords, across Google Patents and Espacenet (both index CN publications and are resolvable — use them as the canonical mirrors for CN documents); WIPO PatentScope, arXiv, IEEE/ACM as applicable; CNIPA's own portal and 知网 are best-effort only (login walls — never block on them, never guess their contents). Forward/backward snowball from seed documents. Each cluster writes `prior-art/candidates-<cluster>.md`: publication number / applicant / publication date / resolvable URL + access date / the specific passages that matter.
   Channel reality check: official portals frequently reject automated access (Espacenet 403, PatentScope is a JS app, Google Patents search UI times out). **Read `references/channels.md` before dispatching** for the tested fallback chain (Justia / Exa / Google Patents per-patent pages / PatSnap Eureka / X技术网 / arXiv API / r.jina.ai …) and have researchers go straight to what works; a blocked channel is recorded as a limitation, never silently skipped. Update `channels.md` with what this round actually found reachable.
   Bibliographic discipline (each learned the hard way):
   - Record **filing date / A-publication date / B-grant date as three separate values** — annotating an A-publication date as the grant date of the B text is a P1 error that propagates into the report and the legal-status table. When a family member gets granted, update status and dates together.
   - An entry known only from a **single mirror source** (application number but no publication number, publication date taken from a re-hosting site) gets an explicit "single-source" flag: mirrors that return an identical page for fabricated IDs prove nothing about existence. Treat official re-verification of such entries as a pre-filing gate, not a suggestion.
   - For NPL, record the **arXiv version and updated date** alongside the ID, and re-check the latest version of every X/Y-grade paper before publishing the report — a v2 can quietly disclose the very feature whose absence the chart relies on (arXiv API `id_list=` batch-fetches versions and authors in one call).
3. **Assess — dispatch `executor`**
   Merge the candidate files, then build `prior-art/claim-chart.md`: each feature from `features.md` × the closest references, citing the exact disclosing passage, each reference tagged with its publication date vs. the cutoff and its role (X — novelty-destroying alone / Y — combinable for inventiveness / A — background only; an E-type conflicting application also compares singly and only for novelty). Then `prior-art/report.md`: novelty (does any single reference disclose all features?), inventiveness (three-step test: closest prior art → distinguishing features → objective technical problem → whether the prior art as a whole gives a teaching/suggestion toward them), and a conclusion — file as-is / strengthen the distinguishing features / drop it — with reasoning.
   Machine-check the chart's own statistics (partial/full-disclosure cell counts, X/Y/A tallies, per-route hit numbers) with grep/awk against the matrices instead of counting by eye — hand tallies drifted three times in one case. When candidate files disagree (a verification level upgraded by a later round, per-route self-reported tallies vs merged tallies), present both readings in the report with the chosen one and why — never silently pick one.
4. **Verify — dispatch `reviewer`** (network track) **+ main session** (local track)
   Check EVERY citation: the URL resolves, and the cited passage actually says what the chart claims. Treat any unverifiable citation as fabricated until proven otherwise. Also check the feature decomposition and the three-step reasoning. The reviewer writes its findings (with reproducible commands and return codes) → `prior-art/review-findings.md`.
   Split the work so a dead subagent doesn't kill the round: the reviewer handles what needs the network (URL reachability for all main references, bibliographic re-checks of high-risk entries, external spot-checks of the strongest quotations); the main session handles local consistency in parallel (report-vs-chart matrix diff, cell-count reconciliation, single-comparison/three-step logic, table integrity, placeholder scan) and logs it alongside. Unreachable ≠ nonexistent — classify each failure as dead link / timeout (retry once via a different channel) / content mismatch. If a dispatch dies mid-run (quota, interruption), re-dispatch with a narrower scope rather than replaying the full task.
5. **Fix — dispatch `executor`**: remove or repair unverified citations first, then P0/P1 issues; max 3 rounds. If P0s remain after round 3, stop and report the open issues to the user. When a fix changes a fact a citation relies on (e.g. a paper's v2 contradicts the v1-based gap argument), re-fetch the primary source and re-grade the affected chart cells per what it actually says — the fix report states what was re-verified and what remains open.
6. **GATE — user approves the report** (AskUserQuestion: approve / adjust). If no answer arrives and the remaining step is a deliverable the original request already named (e.g. generating the PDF), proceed with that reversible step and record the unanswered gate; never treat silence as approval of new scope.
7. **Deliver**: report + chart paths; suggest the next step (`/patent-claims` — the chart feeds the fallback ladder). PDF rendering: if an earlier case in this project already has `prior-art/generate_pdf.py` + `cover_gen.py`, copy and adapt it (three hard-coded spots: header/footer case title, doc metadata, cover content + output path) instead of rebuilding. Use an auto-layout cover template — fixed-coordinate cover templates overlap the hero and summary on long Chinese titles. Visual acceptance runs two rounds via the pdf visual judge: first pass samples every layout class (cover, TOC, body, wide matrix tables, appendix); after fixes, re-judge only the repaired pages.
