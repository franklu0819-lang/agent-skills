# GitHub 短剧/短视频自动生成开源项目调研报告

> 调研日期：2026-10-09
> 调研方式：GitHub REST API + GitHub 页面 HTML 双源交叉验证 star 数与活跃度；README 原文逐个提取 pipeline 细节；GitHub Search API 与社区搜索补充发现
> 受众：个人 agent-skills 仓库维护者（已具备 douyin-video-maker、video-tutorial-gen、ark-video-gen、minimax-video-gen、TTS/ASR 等技能，寻求 pipeline 设计借鉴与自建技能方向）
> 说明：所有 star 数为 2026-10-09 当日数值，均经两个独立来源核验；无法核实之处已明确标注

## 一、结论摘要

1. **MoneyPrinterTurbo 是"全自动口播短视频"赛道的绝对头部**（★129,302，仍在高频迭代），它的定位是"主题 → 文案 → 库存素材 → 配音字幕 → 合成"的通用短视频流水线，**不生成剧情画面**；短剧垂直方向则是 2025-2026 年才爆发的新赛道，头部是 Toonflow（★16,963）和火宝短剧 huobao-drama（★15,891），二者都以"剧本 → 角色/场景资产 → 分镜 → AI 视频逐镜生成 → 拼接成片"为核心链路，深度绑定 Seedance/MiniMax H3/Wan 等国产文生视频模型。

2. **与读者最直接相关的一类项目是"Agent Skill 形态的短剧生产套件"**：zenstory-ai/drama-skills（★2,661，11 个 SKILL.md 技能组成完整产线）与已不可访问的 shuohuo-skills（★4,301，搜索索引残留）证明"不做 Web 平台、纯靠 SKILL.md + 确定性 Python 脚本 + 文件即事实"的路线已经跑通，MoneyPrinterTurbo 官方甚至也发布了 SKILL.md 入口（docs/skill/SKILL.md）。

3. **短剧生成的三大技术共性**：(a) 用"角色/场景资产参考图"解决跨镜一致性（火宝的 @引用参考图、BigBanana 的定妆照+衣橱+首尾关键帧、drama-skills 的连续性锁 LOCK-*）；(b) LLM 负责剧本与分镜结构化（多为 JSON/Markdown 交接格式），生成阶段调用外部视频模型按镜生成；(c) ffmpeg 承担逐镜合成、字幕烧录与整集拼接。**全链路没有一个项目绕开 ffmpeg。**

4. **数字人/口型驱动**（EchoMimicV2 ★4,658、LatentSync ★6,123、Sonic ★3,275）在短剧生态中主要作为可选组件被管线项目引用（如 LangGraph 类项目的 SadTalker 口型节点），而非短剧平台内建能力；对以"漫剧/图片驱动"为主的读者来说优先级不高。

5. **多智能体编排方向**：calderbuild/agentcut（6 Agent 流水线：导演→剧本→视觉/配音/音乐并行→剪辑）、showlab/MovieAgent（★366，学术的多智能体 CoT 规划范式）、wanshuiyin/ARIS-Movie-Director（跨模型审计门禁：一帧生成后由异构模型盲审+确定性 diff 决定 KEEP/RETRY）代表三种编排哲学。用户提到 GraphTV——**经核实 GitHub 上的 GraphTV 是 2017 年的 TV 剧集评分可视化工具，与 AI 视频生成无关**，本报告以实际搜到的项目为准。

6. **已知候选核实结果**：MoneyPrinterTurbo、ShortGPT、NarratoAI 三个项目信息属实、均未归档；其中 ShortGPT 已停滞（最近 push 2025-02-10，约 20 个月无提交），MoneyPrinterTurbo 与 NarratoAI 仍活跃。

## 三、分类详述

### 第一章 全自动短视频 pipeline 类

#### 1.1 harry0703/MoneyPrinterTurbo（★129,302，MIT，活跃）

**一句话**：只需输入主题或关键词，自动完成"脚本→素材→配音→字幕→配乐→合成"的高清短视频流水线，是本赛道事实上的开源标杆。

- **URL**：https://github.com/harry0703/MoneyPrinterTurbo
- **star 数**：129,302（2026-10-09，GitHub API 核验）
- **活跃度**：pushed 2026-10-09，未归档；README 显示近期已升级到"AI Agent / WebUI / API / CLI"四种使用形态，并有 Kimi、火山引擎等多个赞助商。
- **技术栈**：Python 3.11+，Streamlit（WebUI）+ FastAPI（API 服务）+ MoviePy/ffmpeg（合成）；LLM 支持 Kimi/Moonshot、OpenAI、Claude、Gemini、DeepSeek、通义千问、Azure、火山方舟、Grok、MiniMax、小米 MiMo 及各类 OpenAI 兼容网关；素材源 Pexels / Pixabay / Coverr（免费库存）+ 秘塔 MiniMax H3 文生视频 + 火山 Seedance + WaveSpeed + OFox + MuAPI + OpenAI 兼容文生图；TTS 支持 Edge TTS（免费）、Azure Speech V2、SiliconFlow、Gemini TTS、小米 MiMo、MiniMax、ElevenLabs、Chatterbox、Kokoro、Fish Audio、VoxCPM 等 11 家。

**pipeline 拆解**（模块级，模块文件存在性已逐一验证）：

```
输入: 视频主题/关键词（或自定义脚本）
  │
  ├─ ① 脚本生成  app/services/llm.py     → LLM 生成视频脚本，同时提炼"素材搜索关键词"
  ├─ ② 素材获取  app/services/material.py → Pexels/Pixabay/Coverr 按关键词下载库存视频，
  │                                         或调用文生视频/文生图 API 生成原创素材
  ├─ ③ 配音合成  app/services/voice.py    → TTS 生成整段配音（Edge TTS 免费默认）
  ├─ ④ 字幕生成  app/services/subtitle.py → 两种模式：edge=直接用 TTS 时间戳（快、免 GPU）；
  │                                         whisper=本地 faster-whisper 转写（更准，默认 large-v3）
  ├─ ⑤ 任务编排  app/services/task.py     → 串起全流程：片段切分、画幅裁剪（9:16/16:9/1:1）、
  │                                         素材-段落对齐、BGM 混音（音量独立可控）
  ├─ ⑥ 视频合成  app/services/video.py    → MoviePy/ffmpeg 合成 + 字幕烧录（字体/位置/颜色/描边可配）
  └─ ⑦ 交付      cli.py / main.py / webui → API 文档、CLI（支持 --batch-file 批量清单）、
                                            一键发布 TikTok/Instagram/YouTube Shorts
```

**可借鉴点**（对自建 skill 最有价值）：
1. **官方已提供 SKILL.md**（`docs/skill/SKILL.md`），定位是"Agent 读取 skill 文档并操作本地终端"，缺 API Key 时向用户询问，最后返回视频文件路径——这是"开源 pipeline 封装成 skill"的直接范本。
2. **批量任务设计**：CLI 支持 `--batch-file`（JSON 数组/JSONL 清单，上限 100 任务/1MiB），所有条目**先做参数与本地文件预检再启动**；单个任务失败不阻塞后续，结束输出统一 JSON 汇总。
3. **字幕双通道**：TTS 时间戳直出（零成本）与 whisper 转写（高精度）可配置切换，这对"TTS 时长对齐"问题是很好的分层方案。
4. **LLM 顺带产出素材搜索词**：脚本生成时同时要求模型给出每段的关键词，供素材检索使用——把"文案质量"和"素材命中率"耦合在一个 prompt 里解决。

#### 1.2 RayVentura/ShortGPT（★8,010，MIT，已停滞）

**一句话**：最早的短视频自动化 Python 框架之一，用"Engine 抽象"组织自动化内容生产。

- **URL**：https://github.com/RayVentura/ShortGPT
- **star 数**：8,010（2026-10-09 核验）
- **活跃度**：**最近 push 2025-02-10，此后约 20 个月无提交；未归档但实质停滞**。读者引用其 star 数时应注明此点。
- **技术栈**：Python + Moviepy（渲染）+ OpenAI（脚本与 prompt）+ ElevenLabs / EdgeTTS（配音）+ Pexels（背景素材）。

**pipeline 拆解**（按其四个 Engine）：
- `ContentShortEngine`：脚本生成 → 素材 → 配音 → 渲染 → 附加 YouTube 元数据，一条龙出 Shorts；
- `ContentVideoEngine`：面向长视频——生成音频、自动检索背景视频、字幕时间轴、背景资产准备；
- `ContentTranslationEngine`：视频/YouTube 链接 → 转写 → 翻译 → 目标语言配音 → 加字幕 → 输出新语言视频；
- `EditingEngine`：**Editing Markup Language（编辑标记语言，JSON 格式）**——把剪辑过程拆成 LLM 可理解、可生成的块。

**可借鉴点**：Editing Markup Language 是"LLM 输出结构化剪辑指令 → 确定性渲染器执行"这一模式的早期范本，比很多 2025 年后项目的 JSON 剪辑单更早；四个 Engine 的职责划分（成片/长视频/翻译/剪辑）仍适用于 skill 的能力分层。但依赖（ElevenLabs、Pexels、OpenAI）与代码组织已明显老化，不建议直接复用代码。

#### 1.3 linyqh/NarratoAI（★11,337，MIT，活跃）

**一句话**：给**已有**影视/短剧素材自动写解说文案并剪辑成片的工具（"解说"方向，而非"从零生成剧情"），基于 MoneyPrinter/MoneyPrinterTurbo 重构。

- **URL**：https://github.com/linyqh/NarratoAI
- **star 数**：11,337（2026-10-09 核验）
- **活跃度**：pushed 2026-09-17；2026-07-16 发布 v0.8.6。注意：README 明确它是基于 MoneyPrinter 与 MoneyPrinterTurbo 重构而来。
- **技术栈**：Python / Streamlit / ffmpeg；视频理解支持 Qwen2-VL、TwelveLabs Pegasus（整段理解挑高光）；TTS 支持豆包、腾讯云、硅基流动、IndexTTS-1.5/2（含 Apple Silicon MLX 本地语音克隆）、OmniVoice；支持 Fun-ASR 一键转录、AI 配乐（Sonilo）、导出剪映草稿。

**pipeline 拆解**（解说向）：
```
输入: 一段影视/短剧视频文件
  → 抽帧+视觉 LLM 理解（Qwen2-VL/Pegasus，v0.7.8 重构了逐帧分析链路：抽帧、缓存、视觉并发）
  → LLM 生成解说文案（对齐画面段落）
  → TTS 配音（多引擎/可克隆音色）
  → 字幕生成（含 Fun-ASR 转录）
  → 按文案时间轴自动剪辑原片 + 合成解说成片（可导出剪映草稿二次编辑）
```

**可借鉴点**：
1. **"短剧解说"是其 0.6.0 起的独立场景**——对读者的 agent-skills 仓库而言，NarratoAI 的链路（视觉理解→文案→配音→对齐剪辑）可抽成独立的"影视解说 skill"，与"短剧生成 skill"互补；
2. **剪映/CapCut 草稿导出**值得借鉴：把合成结果落成可人工精修的工程文件，而不是只给死成片；
3. 逐帧分析链路的**缓存与视觉并发**设计（0.7.8 专门重构）说明"多模态调用成本控制"是这类工具的核心工程问题。

#### 1.4 FujiwaraChoki/MoneyPrinter 与 MoneyPrinterV2（★14,039 / ★32,076）

- **MoneyPrinter**（原型）：MoviePy 自动生成 YouTube Shorts 的早期爆款项目，是 MoneyPrinterTurbo 与 NarratoAI 的共同灵感来源。pipeline：主题 → LLM 脚本 → 搜索背景素材 → TTS → 字幕 → MoviePy 合成。代码已较老，看价值大于用价值。
- **MoneyPrinterV2**（★32,076，2026-09-15 仍有 push）：定位是"自动化在线赚钱"套件，视频只是其中之一——还含 Twitter Bot（CRON 调度）、YouTube Shorts Automator（CRON 定时发布）、亚马逊联盟营销、本地商家拓客。**视频 pipeline 本身不如 MoneyPrinterTurbo**，其特色是"内容生产 + 定时发布 + 变现"的全链路自动化思路。Python 3.12。

**可借鉴点**：MPV2 的 scheduler（CRON 定时生成+发布）提示 skill 设计可以把"生成"与"发布"拆成两个可独立调度的阶段。

### 第二章 短剧垂直方向（本章为读者核心关注）

短剧/漫剧（动态漫画）生成的完整链路可概括为：**原著/点子 → 分集剧本 → 角色/场景/道具资产 → 参考图 → 分镜 → 逐镜视频提示词 → AI 视频生成（Seedance/MiniMax H3/Wan 等）→ 逐镜合成+字幕 → 整集拼接**。以下项目按 star 与成熟度排列。

**一句话**：开源"AI 短剧工厂"——把剧本创作、资产管理、图像与视频生成整合进一张**无限画布**的可视化创作平台。

```

**可借鉴点**：
1. **无限画布 = 可视化的 pipeline 状态**：剧本、资产、分镜、成片片段以节点形式共处一图，人工可拖拽修补任意环节——skill 化时对应"中间产物目录结构 + 状态清单文件"；

$short-drama-develop        可追溯改编、分集地图、导演阐述、题材钩子手册（断点续做，不整稿塞上下文）

$short-drama-edit           剪辑：逐镜可用带、入出点理由、镜序、台词完整性、字幕、响度 → 剪辑单 + 渲染

（$short-drama 负责初始化、路由、Look Development 与本地 Dashboard）
```

**独到的工程机制**（全部出自 README 与真实示例）：
1. **五份 Markdown 就是创作事实**：每集只维护 `剧本.md / 视觉设定.md / 分镜.md / 图片提示词.md / 视频提示词.md`（剪辑时加 `剪辑单.md`），没有并行数据库——"改哪份文件就是改哪层决定"；
2. **连续性锁（LOCK-*）**：需要跨镜保持的造型写成一条"能原样贴进提示词的短语"，每镜声明依据了哪些锁；`creator_markdown_check.py` 确定性脚本核对引用，漏写会报具体原因（如"分镜时长 2 秒与视频提示词 3 秒不一致"）；
3. **参考图三态管理**：`IMG-*`（项目内图片）/ `PLAN-*`（计划要挂、还没生成）/ `REF-*`（已实际检查过）——支持"图在用户自己界面里生成"的解耦工作流；
4. **确认闸门**：任何花钱的外部调用（图/视频/TTS/音乐）先在文件里看到精确预览，确认后才执行；
5. **孤儿任务恢复**：任务提交即落盘供应商任务 ID；进程中断后 `audit` 报告 `orphaned_provider_job`，`collect --job-id` 免费取回结果，**不重复计费**；
6. **对白估时**：分镜阶段按 MiniMax H3 中文约 4.1 个可发声字/秒估算对白时长，放不下就延长镜头或拆镜——TTS/口播与镜长的对齐在分镜期解决，而不是合成期；
7. 实测样片：68 秒竖屏、20 镜、视频生成成本约 40 元（成本基准可参考）。

**可借鉴点**：这是读者**必读**项目——它就是"短剧生成 agent-skill 化"的完整参考实现。最值得抄的是：文件即事实（Markdown 多文档交叉引用 + 确定性校验脚本）、确认前置的成本闸门、孤儿任务恢复、模型方言分层（视频提示词按目标模型生成不同格式）。

### 第三章 数字人/口型/表演驱动（简要）

### 第四章 多智能体视频生产框架

## 四、对自建 Agent Skill 的启示

综合 30 余个项目的 pipeline 设计，提炼出 5 条共性（按重要性排序）：

### 1. 双层架构：LLM 产出"结构化创作事实"，确定性脚本负责校验与合成
所有成熟项目都把管线切成两层——**创作层**（剧本/分镜/提示词，由 LLM 生成、可被人编辑）与**执行层**（校验、素材生成调用、ffmpeg 合成，纯确定性代码）。drama-skills 用五份 Markdown + `creator_markdown_check.py` 校验引用一致性；ShortGPT 用 Editing Markup Language；火宝用数据库 + Mastra Agent。对 skill 而言最佳形态是：**中间产物全部落盘为人可读的 Markdown/JSON（文件即事实），每个阶段产出一个文件，配一个不花钱的 Python 校验脚本兜底**。这样天然获得：断点续跑（文件在即可继续）、可人工修补、可 diff 版本管理。

### 2. 角色一致性靠"资产前置 + 参考图绑定"，不靠提示词碰运气
这是短剧区别于普通短视频的核心难题，三种成熟方案：(a) **资产库先行**——先为角色/场景/道具生成统一风格的定妆照，逐镜生成视频时作为参考图注入（火宝 @引用、SceneGen r2va 参考图≤9）；(b) **连续性锁**——把需要跨镜保持的造型写成可原样贴进提示词的短语，逐镜声明依据（drama-skills LOCK-*）；(c) **首尾关键帧插值**——每镜只定起止两帧，运动交给模型（BigBanana）。自建技能应至少实现 (a)+(b)，成本敏感时用 (c)。

### 3. 成本闸门与孤儿任务恢复是生成类 skill 的生命线
视频生成按秒计费且不可退。drama-skills 的机制值得整套照搬：**任何外部调用先在文件中预览精确的任务清单（数量/内容/参数/费用），用户确认后才执行**；任务提交那一刻就把供应商任务 ID 落盘，中断后 `audit` 识别孤儿任务、`collect` 免费取回，绝不盲目重投。MoneyPrinterTurbo 的"批量清单先全量预检、单任务失败不阻塞、结束统一 JSON 汇报"是同一思想的批量版。

### 4. 时长对齐要在分镜期解决，而不是合成期
对白赶读/截断是高频翻车点。drama-skills 在分镜阶段就按目标模型的语言语速（MiniMax H3 中文约 4.1 可发声字/秒）估算台词时长、决定镜长或拆镜；MoneyPrinterTurbo 提供字幕双通道（TTS 时间戳直出 vs whisper 转写）。自建技能应：**TTS 先行取时长 → 分镜按时长定镜长 → 视频生成参数（时长）原样照抄已接受的分镜值**，三层用同一份时长字段打通。

### 5. 模型方言分层 + 失败重试是一等公民
同一分镜要能产出不同目标模型的提示词（drama-skills 为 MiniMax H3 写了专门的六段式"方言"文档；火宝在顶栏切换 Seedance/Wan/MiniMax 并按模型给出分辨率档位），skill 应把"目标模型 profile"设计成显式配置而非硬编码。同时，生成失败是常态：批量生成 + 失败一键重试（火宝）、内容审核失败自动提示换模型（火宝）、拼接前校验文件存在（火宝/SceneGen）都应进入默认流程。

### 一句话总结推荐路线
读者已有 ark-video-gen / minimax-video-gen / TTS 等原子技能，最自然的演进是：**新增一个"短剧制片"编排技能**（借鉴 drama-skills 的五文件事实层 + 确认闸门 + 孤儿恢复），以"剧本/分镜 JSON schema + 角色资产参考图 + TTS 时长对齐 + ffmpeg 合成"为主干，把现有视频生成与 TTS 技能作为被编排的下游 adapter——不必自建平台，先把"文件即事实 + 校验脚本"的骨架搭起来。
