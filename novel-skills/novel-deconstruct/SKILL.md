# 拆书工作流

对单本爆款做纵向深挖，回答两个问题：**它凭什么留住读者；哪些零件能拆下来装进我们的书**。产出不是读后感，是模块库——novel-outline 拿主线骨架、novel-opening 拿黄金三章打法、novel-chapter 拿桥段与钩子、novel-style 拿文风要点。

与 novel-research 的分工：research 是立项前的横向对比（3-5 本选方向）；deconstruct 是立项后的纵向逆向（1 本学写法，写作全程可反复调用）。

**跨书指令库**：`references/拆解指令库.md` 累积历次拆书验证过的写作指令，每条带题材适用/不适用标签（通用层 G / 超凡体系 P / 男频家国 M / 文化非遗 C / 长篇结构 L + 负面禁区）。下游技能（outline/volume/chapter/characters/worldview/opening）引用拆书产物前，先读该库按当前作品题材族筛选——**不适用条目明确跳过，禁止当通用规则套用**。

## 派发规则

- 子智能体每次派发都是全新会话：prompt 必须自包含（目标书名、原文路径或公开信息范围、拆解模板、产物路径），不得写"如前所述"。
- 逐章提取类大批量任务按批派发（每批 ≤10 章），并发 ≤3（全局 AGENTS.md），多批分批。
- 与用户交流一律中文。

## Pipeline

0. **状态检查（断点续跑）** — `books/<book>/deconstruct/<目标书>/拆书进度.md` 已存在且未标完成 → 只读该文件，从断点阶段继续；已完成阶段不重拆。会话可能中断多次，进度文件是唯一状态权威。
1. **定对象** — AskUserQuestion 补齐三件事：
   - 目标书：书名 + 平台（书名必须真实存在，不得虚构）
   - 原文获取方式：**原文文件**（txt/md 路径，首选）→ 全流程可跑；**无原文** → 降级"浅拆"（基于公开书评/章节目录/读者讨论做 L1/L3/L5，跳过 L2/L4/L6），所有产物头部标注"未获取原文，基于公开信息，结论供假设用"，并建议用户补原文复拆黄金三章
   - 拆解范围：全书 / 前 N 卷 / 仅黄金三章（默认：黄金三章 + 前 50 章 + 完结卷的收尾 3 章）
2. **L1 宏观骨架** — 核心设定与金手指（一句话说清"爽的引擎"）、主线三幕对应到卷、每卷功能（升级/换地图/立对手）、体量与成绩量级（附来源）。
3. **L2 黄金三章细拆**（需原文）— 逐章四问：开场第一句做了什么（悬念/冲突/反差/信息量）；信息释放顺序（读者第几段知道主角底牌）；第一个爽点出现在多少字处、什么类型；章末钩子类型（用桥段词表的钩子标签）。对齐 novel-opening 的留存视角——这三章的每个决策点都要标注。
4. **L3 节奏与爽点频谱** — 抽样 ≥30 章（含开头/中段/高潮章）统计：爽点类型分布与出现频率（平均几章一个）、小高潮间隔、大高潮（卷末）前后的铺垫章数、追读钩子的模式清单（每类给一个原文定位）。
5. **L4 桥段库**（需原文）— 从抽样章提取可复用桥段，每条按固定格式（见下）；用 `references/桥段词表.md` 的统一标签打标，禁止自造同义标签。
6. **L5 人物公式** — 主角人设四元组（身份/欲望/障碍/反差）、金手指与性格的耦合方式、配角功能位清单（导师/对手/损友/红颜/工具人各起什么节奏作用）、关系动态模式（何时引入新关系、何时打破旧关系）。
7. **L6 文风画像** — 句长分布（短句为主还是长句为主）、对白/叙述/描写比例、章均字数、标志手法（口头禅、视角切换习惯、数字量词风格）。只输出三条"可模仿要点"，**不给仿写样本**——学结构不抄表达，防文风抄袭。
8. **落盘与登记** — 产物按下方结构写入 `books/<book>/deconstruct/<目标书slug>/`；每完成一个 L 层即更新 `拆书进度.md`（阶段打勾 + 已拆章号区间），不要等全完。
9. **GATE + 交付** — 汇报：模块库文件清单 + "最值得抄的三件事"（各附一句理由）；AskUserQuestion 问两件事：是否把验证有效的桥段并入全局 `books/<book>/modules/桥段库.md`（新建或追加，保留出处标注）；是否把本次提炼的跨书指令登记进 `references/拆解指令库.md`（按库内登记规则：分层编号、来源、适用与不适用标签——**指令必须标注题材边界，禁止无条件的通用化**；同义合并、冲突择优）。交付后建议：写大纲前把 L1/L3 给 novel-outline，开篇前把 L2 给 novel-opening。用户要求导出 PDF 时，文件名带书名（如 `拆书报告-我在精神病院学斩神.pdf`）。

## 产物结构

```
books/<book>/deconstruct/<目标书slug>/
├── 拆书进度.md      # 状态层：阶段勾选表、已拆章号区间、原文路径、断点说明
├── 拆书报告.md      # 决策级主报告（≤150 行）：五层结论速览 + 模块库索引
├── 黄金三章拆解.md  # L2 逐章四问
├── 节奏与爽点.md    # L3 频谱与钩子清单
├── 桥段库.md        # L4 模块库（novel-chapter 写作时直接引用）
├── 人物拆解.md      # L5 公式与功能位
└── 文风画像.md      # L6 三条可模仿要点（novel-style 参考）
```

`拆书进度.md` 模板：

```markdown
# 《目标书》拆书进度
原文：<路径或"无，浅拆模式">　范围：<黄金三章+前50章 等>
| 阶段 | 状态 | 产物 |
|---|---|---|
| L1 宏观骨架 | ☐/☑ | 拆书报告.md |
| L2 黄金三章 | ☐/☑ | 黄金三章拆解.md |
| L3 节奏频谱 | ☐/☑ | 节奏与爽点.md |
| L4 桥段库 | ☐/☑ | 桥段库.md |
| L5 人物公式 | ☐/☑ | 人物拆解.md |
| L6 文风画像 | ☐/☑ | 文风画像.md |
断点：<上次中断在哪一章哪一批；无则写"无" >
```

## 桥段条目格式（L4 固定字段）

```markdown
### [标签] 桥段名（≤10 字）
- 场景前提：谁在哪、处于什么劣势/优势
- 冲突：什么事打破平衡
- 反转：读者预期 A，实际发生 B
- 情绪落点：读者此刻的情绪（爽/燃/酸/怕/释然）
- 出处：第 N 章（附 5-15 字定位词）
- 移植度：高/中/低——换题材换皮还能不能用，一句理由
```

**合格标准**：桥段必须是"可移植结构"而非剧情复述——把人物名字全换掉仍然成立的才算合格；移植度低的条目不录入。

## 质量要求

- 硬事实（桥段、爽点位置、钩子）必须附章节定位（第 N 章 + 5-15 字定位词）；推断性结论标"（推断）"；无原文模式下不得出现任何具体章节内容描述。
- 数据宁缺毋滥：成绩与体量数据附来源，查不到写"未能核实"，禁止编造。
- L2-L6 是给机器和作者共用的素材库：条目格式统一、标签只用词表内的，保证 novel-chapter 跨本调用时无需重新理解格式。
- 拆书报告.md 是决策文件不是资料堆：≤150 行，每层结论不超过五行，细节都在对应模块文件里。
- 版权边界：拆结构与手法，不复述原文段落；文风画像只给要点不给样本。
