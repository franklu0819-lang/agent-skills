# 小说题材调研工作流

动笔之前回答三个问题：**这个题材有没有读者、读者在爽什么、本书靠什么差异化**。产出一份能直接支撑大纲决策的调研报告。用 TodoWrite 跟踪。

## 派发规则

- 子智能体每次派发都是全新会话：prompt 必须自包含（题材、平台、产物路径、具体拆解项），不得写"如前所述"。
- 并发 ≤3（全局 AGENTS.md），多批调研分批派发。
- 与用户交流一律中文。

## Pipeline

1. **定范围** — 确定三件事，用户未给的用 AskUserQuestion 补齐：
   - 题材/赛道（玄幻、都市、仙侠、历史、科幻、悬疑、女频……）
   - 目标平台（起点、番茄、七猫、晋江、飞卢……）——平台决定爽点密度与节奏基准
   - 本书书名或 `<book>` slug（英文短横线，如 `dushi-chongsheng`）；没有就从题材+核心创意生成一个，交付时告知用户
2. **市场调研 — dispatch `researcher`**
   要求输出：题材近 1–2 年热度趋势与代表新作、目标读者画像（年龄、付费习惯、追更场景）、平台推荐机制下的热门标签、题材红海/蓝海判断。每条结论附来源。
3. **竞品拆解 — dispatch `researcher`**（与步骤 2 可同批派发，合计 ≤3）
   选 3–5 部**近期**成绩好的同类作品（书名必须真实存在），逐本拆解：
   - 核心设定与金手指是什么、入场多快
   - 开头黄金三章各做了什么（第一章给了什么爽点）
   - 主要爽点类型与大致出现节奏（几章一个）
   - 读者评论/书评区的高频抱怨（雷点：圣母、降智、注水、烂尾……）
   - 体量与成绩量级
4. **汇总落盘** — 主智能体将两批结果合成一份报告，目录不存在则创建，写入：
   `books/<book>/research/题材调研报告-YYYY-MM-DD.md`（用今天日期）
5. **GATE** — AskUserQuestion 让用户拍板差异化方向：给出 2–3 个候选方向（如"退婚流+反派视角""无敌流+苟道日常"），各附一句差异化理由与风险。
6. **交付** — 报告路径 + 五行以内结论摘要；建议下一步 `/novel-outline <book>`。

## 报告结构（照此模板写）

```markdown
# 《<书名>》题材调研报告（YYYY-MM-DD）

## 1. 结论速览
（三行以内：题材判断 / 读者要什么 / 本书差异化方向）

## 2. 市场与读者
### 2.1 题材热度趋势
### 2.2 读者画像与付费偏好
### 2.3 平台风向与热门标签

## 3. 竞品拆解
### 3.1 《竞品A》：金手指｜黄金三章｜爽点节奏｜雷点｜成绩
### 3.2 《竞品B》：……

## 4. 套路与爽点清单
（从竞品中归纳：本题材被验证有效的爽点类型，标注出现频率）

## 5. 雷点清单
（读者用脚投票的坑，写作时规避）

## 6. 差异化建议
（候选方向 2–3 个：定位 + 理由 + 风险，供用户 GATE 拍板）

## 附：信息来源
（作品页/榜单/书评区链接；查不到的写"未能核实"，禁止编造）
```

## 质量要求

- 数据宁缺毋滥：所有平台数据、成绩描述须有来源，查不到就明说，**不得虚构书名、数据或榜单排名**。
- 竞品优先选近 2 年内仍在更新或完结不久的作品，老书只作套路参考。
- 报告控制在 150–300 行：它是决策文件，不是资料堆。
