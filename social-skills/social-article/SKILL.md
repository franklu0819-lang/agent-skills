# 文章内容生成（微信公众号 + 头条号）

产出**文章内容包**：标题候选 + 正文 + 摘要 + 配图，支持公众号与头条号两个平台。一次请求可能只要其中部分产物，先确认再动手，不要默认全做。

## 第一步：澄清需求

若用户未给出以下信息，合并成一轮提问补齐（不要挤牙膏式追问）：

| 要素 | 说明 | 缺省默认 |
|---|---|---|
| 平台 | 公众号 / 头条号 / 两者 | 必填，无默认 |
| 主题与目的 | 新品推广 / 干货科普 / 活动通知 / 观点输出 | 必填，无默认 |
| 受众 | 决定语言正式度与术语密度 | 面向大众读者 |
| 产物 | 文案 / 文案+配图 | 文案+配图 |
| 调性 | 专业 / 亲切 / 活泼 / 高级感 | 专业而亲切 |
| 品牌信息 | 名称、slogan、主色（#hex） | 用 `assets/brand.md` 品牌色板（XIAOFEI'S AI BUSINESS NOTES，深蓝+青蓝+金），模板已内置 |

用户给出「参考上一篇的调性」这类指示时，先读 `docs/marketing/` 下的历史产物再动笔，不要凭空猜。

## 第二步：写文案

先读 `references/copywriting.md`（平台差异、标题公式、正文结构、合规禁用词），然后：

1. 产出 **3–5 个标题候选**（头条 2–3 个），各自标注手法与汉字当量（公众号 ≤20 当量）；
2. 按平台结构写正文：公众号「钩子 → 小标题分段 → CTA」，头条「开头即亮点 → 小标题+配图 → 引导评论」；
3. 公众号另写 **≤120 字摘要**；
4. 对照合规禁用词表自检，命中即改写；
5. 交付前跑长度校验，全绿才算完：

```bash
python3 <本技能目录>/scripts/len_check.py file copy.md
```

文案落盘 `docs/marketing/<slug>/copy.md`（slug = 主题英文短词；用户指定目录则从用户），结构见 copywriting.md 末尾示例。

## 第三步：配图

先读 `references/image-specs.md`（尺寸、设计规则、渲染流程），按需做：

- **正文小节横幅** 900×500、**金句卡/朋友圈图** 1080×1080：改 `assets/templates/` 模板 → chrome-devtools 截图出 PNG；
- **AI 生图配图**（插画/场景图，无文字）：调 ark-image-gen，横图 16:9 或 3:2；
- **3:4 贴图组**（多张信息卡 + 配套文案）：不在本技能，交给 social-cards 技能；
- **公众号文章封面**：由 wechat-mp-draft 技能在排版提交流程里生成（规范见其 references/cover.md）；
- **头条文章封面**：无提交流程，随内容包直接出图，16:9（AI 生图或横幅模板改画布尺寸）。

## 交付

- 列出所有产物的绝对路径链接；贴出选定标题 + 摘要供快速过目，正文指出所在文件。
- 图给路径与尺寸，PNG 直接可用。
- 用户要微调时在现有产物上迭代，不重走全流程。
- 后续要发公众号：把 copy.md 交给 wechat-mp-draft 技能（排版 + 封面 + 提交草稿箱）。

## 边界与依赖

- 只生成内容与图片文件；**不提交、不发布**——提交公众号草稿箱是 wechat-mp-draft 技能的职责。
- 图中含大段中文文字的一律走 HTML 模板渲染（AI 生图中文几乎必错）；AI 生图仅用于无文字背景/插画，提示词注明「无任何文字」。
- 内容要点（事实、数据、来源）必须已给定；缺素材先停下要素材或先调研，**严禁编造**。
- 依赖：ark-image-gen（AI 配图，用户级技能）、chrome-devtools MCP（模板渲染出图）；social-cards（3:4 贴图组）与 wechat-mp-draft（公众号草稿提交）为兄弟技能，按需引导用户。
